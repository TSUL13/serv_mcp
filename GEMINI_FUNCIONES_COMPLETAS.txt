FUNCIONES BÁSICAS (4)
═════════════════════

1. listar_dispositivos
   Descripción: Lista todos los dispositivos SD-WAN en la red con su estado
   Parámetros: Ninguno
   Endpoint: GET /devices
   
   Ejemplo: "¿Cuántos dispositivos hay en la red?"
   Ejemplo: "Muéstrame todos los dispositivos"

2. salud_dispositivo
   Descripción: Obtiene el estado de salud detallado de un dispositivo
   Parámetros: device_id (System IP)
   Endpoint: GET /devices/{id}/health
   
   Ejemplo: "¿Cómo está el router 10.1.1.1?"
   Ejemplo: "Dame la salud del dispositivo 172.16.1.1"

3. sesiones_bfd_dispositivo
   Descripción: Obtiene todas las sesiones BFD de un dispositivo específico
   Parámetros: device_id (System IP)
   Endpoint: GET /devices/{id}/bfd
   
   Ejemplo: "Muéstrame las sesiones BFD del 10.1.1.1"
   Ejemplo: "¿Cuántas sesiones BFD tiene el router 172.16.1.1?"

4. obtener_alarmas_criticas
   Descripción: Obtiene las alarmas críticas activas en la red
   Parámetros: Ninguno
   Endpoint: GET /alarms/critical
   
   Ejemplo: "¿Hay alarmas críticas?"
   Ejemplo: "Muéstrame las alarmas más graves"


FUNCIONES FASE 1 - Monitoreo Avanzado (5)
══════════════════════════════════════════

5. estadisticas_interfaces
   Descripción: Estadísticas detalladas de interfaces de un dispositivo
   Parámetros: device_id (System IP)
   Endpoint: GET /devices/{id}/interfaces
   
   Ejemplo: "Muéstrame las interfaces del router 10.1.1.1"
   Ejemplo: "¿Qué interfaces tiene el dispositivo 172.16.1.1?"

6. uso_cpu_memoria
   Descripción: Uso de CPU y memoria de un dispositivo
   Parámetros: device_id (System IP)
   Endpoint: GET /devices/{id}/cpu-memory
   
   Ejemplo: "¿Cuál es el uso de CPU del 10.1.1.1?"
   Ejemplo: "Revisa la memoria del router 172.16.1.1"

7. tuneles_omp
   Descripción: Información de túneles OMP de un dispositivo
   Parámetros: device_id (System IP)
   Endpoint: GET /devices/{id}/omp-tunnels
   
   Ejemplo: "Muéstrame los túneles OMP del 10.1.1.1"
   Ejemplo: "¿Cuántos peers OMP tiene el dispositivo 172.16.1.1?"

8. conexiones_control
   Descripción: Conexiones de control activas en la red
   Parámetros: Ninguno
   Endpoint: GET /control-connections
   
   Ejemplo: "¿Cuántas conexiones de control hay?"
   Ejemplo: "Muéstrame las conexiones activas"

9. obtener_resumen_red
   Descripción: Resumen completo del estado de la red
   Parámetros: Ninguno
   Endpoint: GET /network-summary
   
   Ejemplo: "Dame un resumen de la red"
   Ejemplo: "¿Cómo está la red en general?"


FUNCIONES FASE 2 - Análisis y Búsqueda (5)
═══════════════════════════════════════════

10. aplicaciones_top
    Descripción: Top aplicaciones con mayor tráfico
    Parámetros: Ninguno
    Endpoint: GET /applications/top
    
    Ejemplo: "¿Qué aplicaciones generan más tráfico?"
    Ejemplo: "Muéstrame las aplicaciones más usadas"

11. buscar_dispositivo
    Descripción: Busca dispositivos por campo y valor
    Parámetros: field (host-name, site-id, etc), value
    Endpoint: GET /search?field=X&value=Y
    
    Ejemplo: "Busca dispositivos que contengan 'CDMX'"
    Ejemplo: "Encuentra routers del sitio 100"

12. dispositivos_por_sitio
    Descripción: Lista dispositivos de un sitio específico
    Parámetros: site_id
    Endpoint: GET /sites/{id}/devices
    
    Ejemplo: "¿Qué dispositivos hay en el sitio 100?"
    Ejemplo: "Muéstrame los equipos del sitio CDMX"

13. eventos_seguridad
    Descripción: Eventos de seguridad de la red
    Parámetros: Ninguno
    Endpoint: GET /security/events
    
    Ejemplo: "¿Hay eventos de seguridad?"
    Ejemplo: "Muéstrame las alertas de seguridad"

14. diagnostico_completo
    Descripción: Diagnóstico completo de un dispositivo
                 (salud + BFD + interfaces + OMP)
    Parámetros: device_id (System IP)
    Endpoint: GET /devices/{id}/diagnostic
    
    Ejemplo: "Dame un diagnóstico completo del 10.1.1.1"
    Ejemplo: "Analiza completamente el router 172.16.1.1"


FUNCIÓN ESPECIAL - BFD Total (1)
═════════════════════════════════

15. obtener_total_sesiones_bfd
    Descripción: Cuenta total de sesiones BFD en toda la red
    Parámetros: sample_size (opcional, default: 10)
    Endpoint: GET /bfd/total?sample_size=X
    
    Ejemplo: "¿Cuántas sesiones BFD hay en total?"
    Ejemplo: "Cuenta todas las sesiones BFD (usa sample_size=332)"

ANÁLISIS MULTI-FUNCIÓN:
──────────────────────

Gemini puede combinar funciones automáticamente:

Usuario: "¿Por qué el sitio 100 tiene problemas?"

Gemini ejecuta:
  1. dispositivos_por_sitio(site_id="100")
  2. Para cada dispositivo:
     - salud_dispositivo(device_id)
     - sesiones_bfd_dispositivo(device_id)
  3. obtener_alarmas_criticas
  4. Analiza y correlaciona resultados

Respuesta: "El sitio 100 tiene 5 dispositivos, 2 están caídos:
            - SDWAN-SITE100-RT01: Offline hace 2 horas
            - SDWAN-SITE100-RT02: Alta CPU (95%)
            Alarma crítica activa: 'Control Connection Down'
            Recomendación: Revisar conectividad WAN"


DIAGNÓSTICO PROACTIVO:
─────────────────────

Usuario: "Revisa todos los dispositivos con alta CPU"

Gemini ejecuta:
  1. listar_dispositivos
  2. Para cada dispositivo:
     uso_cpu_memoria(device_id)
  3. Filtra los que tienen CPU > 80%
  4. Para cada uno con alta CPU:
     diagnostico_completo(device_id)

Respuesta: "Encontrados 3 dispositivos con alta CPU:
            1. SDWAN-RT-05: CPU 95% - Alta carga de tráfico
            2. SDWAN-RT-12: CPU 87% - Proceso anómalo
            3. SDWAN-RT-23: CPU 82% - Normal para ese dispositivo
            Recomendación: Investigar SDWAN-RT-12"


ANÁLISIS DE TENDENCIAS:
──────────────────────

Usuario: "¿Qué sitios tienen más dispositivos caídos?"

Gemini ejecuta:
  1. listar_dispositivos
  2. Agrupa por site-id
  3. Para cada sitio con dispositivos caídos:
     dispositivos_por_sitio(site_id)
  4. Ordena por cantidad de fallos

Respuesta: "Sitios con dispositivos caídos:
            1. Sitio 100: 2 dispositivos caídos de 5
            2. Sitio 250: 1 dispositivo caído de 3
            3. Sitio 340: 2 dispositivos caídos de 8
            Total: 5 dispositivos caídos en 3 sitios"
